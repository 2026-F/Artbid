# 관리자 경매 수동 시작과 마감 제한

- 작성일: 2026-11-10
- 관련 이슈 / PR: [BE #96](https://github.com/2026-F/Artbid/issues/96), [FE #53](https://github.com/2026-F/frontend/issues/53), [FE PR #67](https://github.com/2026-F/frontend/pull/67)

## 목적

수동 시작 후 상세 조회와 실시간 상태를 일치시키고 관리자 상태 변경에서 정산 없이 경매가 닫히는 경로를 차단한다.

## 핵심 요청

요약. 최신 백엔드 develop에서 두 결함을 수정한다. 기존 자동 마감·정산과 재오픈을 유지하고, Kafka를 끈 상태에서 프론트 PR #67과 연동한다.

## 선택과 이유

| 검토한 방법 | 선택 | 이유 |
| --- | --- | --- |
| 행 락 안에서 실시간 변경 이벤트 발행 | 채택 | 입찰과 같은 순서로 버전을 부여하고 기존 커밋 후 리스너가 캐시와 SSE를 갱신한다. |
| 관리자 상태 변경에서 직접 마감 거절 | 채택 | 기존 409 응답과 자동 마감을 사용해 정산 우회를 차단한다. |
| 수동 마감을 기존 마감 서비스에 연결 | 보류 | 수동 마감의 운영 필요성과 호출 시점, 스케줄러 경합을 별도로 검증해야 한다. |

## 반영 내용

- 기존 상태 변경 API의 성공 응답은 204를 유지한다. `CLOSED` 직접 지정은 기존 409 형식으로 거절한다.
- 수동 변경은 경매 행 락 안에서 처리한다. 실제 상태가 바뀌면 기존 `SNAPSHOT` 사유와 변경 버전으로 이벤트를 발행한다.

## 검증

- 격리된 PostgreSQL 16·Redis 7에서 Kafka 리스너와 Outbox 발행을 끄고 Gradle 빌드 및 테스트를 실행했다. 380개 통과, 17개 건너뜀, 실패 0개다.
- 새 회귀 테스트에서 롤백 시 DB·캐시가 유지되고 커밋 후 변경 버전으로 캐시가 갱신되는지, 마감 전후 직접 지정이 409로 거절되고 DB 상태와 정산이 바뀌지 않는지 확인했다.
- 브라우저 연동 검증 결과는 이 변경의 PR에 기록한다.
