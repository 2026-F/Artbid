# AI 협업 문서와 의사결정 기록 체계 도입

- 작성일: 2026-10-26
- 관련 이슈 / PR: 미생성
- 작업 브랜치: `docs/ai-collaboration` (기준: `develop`)

## 목적

멘토 피드백을 반영해 AI 제안, 팀원의 선택 이유, 수정 사항, 검증 결과를 짧게 남기는 협업 방식 마련.

팀 구성은 Claude 사용자 3명, Codex 사용자 1명. 공통 지침은 CLAUDE.md에 두고 AGENTS.md에서 참조.

## 핵심 요청

> 목표는 멘토님 피드백 수용하고 우리 팀원들이 ai를 활용하면서 어떤 의사결정을 내렸는지 효율적으로 기록하며 협업하는 거야.

> PR 템플릿에 AI 활용 부분은 빼고, 이 작업하며 생성된 prompts 히스토리 파일이 뭔지 연결하는 걸로 대체하면 될듯?
> 리뷰시 확인할 사항도 중복되는 듯하니 넣지마

추가 요청 요약:

- 두 저장소의 README 갱신, CLAUDE.md와 AGENTS.md 작성, prompts 폴더 생성
- 보안 지침 보강
- JDBC 실습과 AI 없이 개발하기는 필수 지침에서 제외
- 중간점 사용을 줄이고 자연스러운 문장 사용
- 기록 양식의 담당자, 사용 도구, 담당자 확인 삭제
- 포괄적인 항목을 나누고 불필요한 설명 대신 짧은 요약 사용
- 기존 README의 누락과 코드 불일치를 점검하고 보완
- MSA 분리 예정: 경매/입찰 + 회원/작품, 결제/정산, 라이브 스트리밍. 레포 구조 변경 가능
- 문체는 존댓말 없이 요약체와 하다체만 사용
- README 최종 점검 요청. 명령어는 macOS와 Windows Git Bash 기준으로 통일

> 어 맞아 우리 경매입찰에 Kafka 도입할거거든 Redis를 아예 안쓸지 이런건 아직 어떻게 될지 모르는 상황이야

| 예정된 MSA 서비스 구분과 현재 패키지 구조 분리 | 채택 | 사용자가 세 서비스 경계와 레포 구조 변경 가능성 공유. 저장소 분리 방식과 상세 계약은 미정 |

## 반영 내용

- README: 현재 입찰, 방송, 인증, 결제 구현과 실행 안내 갱신
- 기존 결제 문서: 과거 내용 보존, 상단에 후속 PR 안내 추가
- CLAUDE.md: 공통 작업 방식과 백엔드 보안 기준 작성
- AGENTS.md: CLAUDE.md를 읽도록 안내
- PR 템플릿: AI 활용 설명과 리뷰 확인 항목 대신 작업 기록 링크
- 기록 양식: 목적, 요청, 선택 이유, 반영 내용, 검증, 남은 작업으로 구분
- 후속 수정: 담당자 관련 필드와 사용 도구 삭제, 원문 앞의 설명 문장 제거, 긴 서술을 요약과 표로 정리
- README 재검토: 위탁과 프리뷰 흐름, 담당 영역, 노션 상태 업데이트 복원. HMAC 미구현 상태, 로그아웃 범위, 안티 스나이핑 조건 명시
- 현재 PostgreSQL/SSE 입찰 경로와 Kafka 도입 계획 분리. Redis 유지 또는 제거는 미정으로 기록
- 로컬 S3 초기화의 공개 읽기 정책 안내 추가. README와 CLAUDE.md의 역할 및 요구사항과 코드가 다를 때의 확인 원칙 명시
- MSA 분리 계획과 구조 변경 시 문서, CI, 기록 연결 갱신 원칙 추가. 현재 담당 영역 표와 미래 서비스 경계 구분
- 두 README의 존댓말을 요약체와 하다체로 수정하고 공통 지침에도 반영
- 최종 점검: PowerShell 안내 제거, 결제 통합 테스트를 명령 한정 환경변수 방식으로 변경, 커밋 목록 렌더링과 '필요한다' 표현 수정
- 기록 갱신 규칙 보완: 진행 중인 같은 PR의 기록에 날짜를 구분해 추가하고 이전 판단 보존. 병합 후 후속 작업은 새 파일에서 이전 기록 연결. README, CLAUDE.md, TEMPLATE에 동일하게 반영
- 전체 최종 점검: 기술 스택 표 반영, PR 기록 링크를 전체 URL과 커밋 영구 링크 안내로 수정, 기존 결제 문서에 추가한 안내문의 문체 통일. 방송 방식 설명은 현재 상태와 향후 변경 구분
- README 직접 수정본 반영: 노션 상태 업데이트 안내는 최종본에서 제외된 상태로 유지
