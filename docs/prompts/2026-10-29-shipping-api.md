# 배송 정보 입력·조회·운송장 등록 API

- 작성일: 2026-10-29
- 관련 이슈 / PR: #39, PR 생성 전

## 목적

낙찰자가 낙찰 건의 배송지를 입력하고, 위탁자가 배송지를 확인해 운송장을 등록할 수 있게 한다.
제약: 수령인 이름, 연락처, 주소는 개인정보다. 백엔드에 배송 관련 코드가 없었다. 프론트 회원정보 화면에는 휴대폰, 배송지 입력칸이 저장 API 없이 비활성화돼 있다.

## 핵심 요청

> [회원·결제·정산] 배송 정보 입력·조회·운송장 등록 API #39

이슈 본문은 AI 작업 환경에서 GitHub 접근이 안 돼 확인하지 못했다. 범위는 아래 질문으로 정했다.

요약: AI가 배송지 단위, 운송장 등록 주체, 배송 상태 범위를 물었다.
사용자 선택: 낙찰 건별, 위탁자 본인 + 관리자, 운송장 등록(발송)까지.

## 선택과 이유

| 검토한 방법 | 선택 | 이유 |
| --- | --- | --- |
| 배송지: 낙찰 건(정산)별 | 채택 (사용자 선택, AI 추천) | 이슈 제목과 가장 가까움 |
| 배송지: 회원 기본 배송지 + 건별 | 제외 | 범위가 커짐. 프론트 회원정보 화면의 배송지 저장은 후속 |
| 운송장 등록: 위탁자 본인 + 관리자 | 채택 (사용자 선택, AI 추천) | 역할만이 아니라 작품의 위탁자 본인인지 확인 |
| 배송 상태: READY → SHIPPED | 채택 (사용자 선택) | DELIVERED는 enum에만 정의. 기존 DB CHECK 제약 문제 예방 (정산 배치 작업과 같은 이유) |
| API 위치: `/api/settlements/{id}/shipment` | 채택 (AI 결정) | 결제 API `/api/settlements/{id}/payments`와 같은 기준 |
| 배송지 입력 가능 정산: PENDING, PAID | 채택 (AI 결정) | 결제 전후 모두 입력 가능. FAILED(결제 실패, 기한 만료)는 거절 |
| 운송장 등록 조건: PAID + 배송지 입력 | 채택 (AI 결정) | 결제 전 발송 방지 |
| 발송 후 배송지 수정 | 거절 (AI 결정) | 출발한 택배 주소가 바뀐 것처럼 보이지 않게 함. 운송장 재등록은 번호 수정으로 허용, 최초 발송 시각 유지 |
| 동시 입력 중복 방지: 정산 행 잠금 + settlementId 유니크 | 채택 (AI 결정) | |
| 택배사: 문자열 | 채택 (AI 결정) | 택배사 코드 목록 미정 |
| 개인정보 보호 | 채택 (AI 결정) | 요청, 응답, 값 객체의 toString 마스킹. 검증 오류는 필드 이름만 반환. 예외 메시지에 값 미포함 |

## 반영 내용

- `shipping` 패키지: `Shipment`, `ShipmentStatus`, `ShippingAddress`, 리포지토리, 서비스, 컨트롤러, 예외 처리
- `PUT /api/settlements/{id}/shipment`: 배송지 입력·수정 (낙찰자 본인, 발송 전)
- `GET /api/settlements/{id}/shipment`: 조회 (낙찰자, 해당 작품 위탁자, 관리자)
- `PUT /api/settlements/{id}/shipment/tracking`: 운송장 등록·수정 (해당 작품 위탁자, 관리자)
- 오류 응답: `{code, message}`. 401 AUTH_REQUIRED, 403 SHIPMENT_FORBIDDEN, 404 SETTLEMENT_NOT_FOUND / SHIPMENT_NOT_FOUND, 409 SETTLEMENT_NOT_SHIPPABLE / SETTLEMENT_NOT_PAID / SHIPMENT_ADDRESS_REQUIRED / SHIPMENT_ALREADY_SHIPPED, 400 VALIDATION_ERROR
- README 현재 구현에 배송 항목 추가

## 검증

| 확인 항목 | 방법 | 결과 |
| --- | --- | --- |
| 도메인, 서비스, 컨트롤러 단위 테스트 | `./gradlew build` (AI 작업 환경, Linux, Java 21) | 통과 |
| 실제 DB 흐름과 동시 입력 | PostgreSQL 16 통합 테스트. 같은 정산에 10개 동시 입력 | 배송 정보 1건만 생성 |
| 전체 테스트 | PostgreSQL 16, Redis 7 실행 후 `./gradlew build` | 219개 중 실패 0, 건너뜀 9 (기존 조건부 테스트) |
| 실제 서버 흐름 | `bootRun` 후 회원가입, 로그인 토큰으로 11개 시나리오 호출 | 입력, 수정, 조회, 결제 후 운송장 등록, 발송 후 수정 거절 정상 |
| 권한과 잘못된 입력 | 같은 서버 | 비로그인 401, 위탁자의 배송지 입력 403, 관계없는 회원 조회 403, 낙찰자의 운송장 등록 403, 결제 전 운송장 409, 우편번호 오류 400 |
| 개인정보 로그 노출 | 서버 로그에서 입력한 이름, 연락처, 주소 검색 | 0건 |

미검증: Windows 로컬 실행, 프론트 연동(배송 화면 없음), 실제 택배사 운송장 유효성.
