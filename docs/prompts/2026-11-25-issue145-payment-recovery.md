# MY 결제 복구, 서버 기준 기한 및 알림 연결

- 작성일 2026-11-25
- 관련 이슈 [백엔드 #145](https://github.com/2026-F/Artbid/issues/145), [프론트엔드 #92](https://github.com/2026-F/frontend/issues/92)

## 목적

최초 결제 응답을 받지 못했거나 다른 기기에서 접속한 낙찰자가 정산 ID로 결제를 복구할 수 있게 한다. 결제 기한의 서버 기준을 명시하고 낙찰·결제 완료 알림에 해당 목록으로 가는 링크를 제공한다.

## 핵심 요청

요약 · 인증된 낙찰자에게 진행 중인 결제와 정산 상태를 제공하고, 서버 시각과 기한의 경계 동작을 검증한다. 신규 알림 링크를 연결하고 기존 정산 응답과 저장된 알림을 호환한다. 이슈 #145의 PR 한 개에 조회 API와 기한·알림 변경을 두 커밋으로 구성한다.

## 선택과 이유

| 선택 | 이유 |
| --- | --- |
| 읽기 전용 `REPEATABLE READ` | 두 조회 사이에 승인이 커밋돼도 정산과 결제를 같은 PostgreSQL 스냅샷에서 읽는다. |
| 진행 중인 결제의 ID와 상태만 반환 | 복구에 필요한 정보만 제공한다. |
| 신규 조회에 오프셋 시각을 포함하고 주입 가능한 서울 시계를 사용 | 기존 정산 API 형식을 유지하면서 생성·조회·만료·복구의 시각 기준을 맞추고 기한 경계를 검증한다. |

## 반영 내용

- `GET /api/settlements/{id}/payments/active`에서 검증된 회원이 낙찰자인지 확인한다. 진행 중인 결제가 없으면 `payment: null`을 반환하며, 성공 응답에는 `Cache-Control: no-store`를 적용한다.
- 응답에 서버 시각과 결제 기한을 서울 오프셋과 함께 제공한다. 기한 정각부터 신규 결제를 거절하고, `REQUESTED` 건의 만료는 결과 확정까지 보류한다. [프론트 연동 계약](../payment-recovery-api.md)
- 새 `AUCTION_WON`은 `/mypage/payments`, 새 `PAYMENT_COMPLETED`는 `/mypage/orders`로 연결한다. 기존 수신자와 발행 조건을 유지한다.
